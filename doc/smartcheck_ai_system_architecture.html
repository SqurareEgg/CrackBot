핵심 설계 원칙
1
모바일 퍼스트 (Offline-tolerant)
현장 네트워크가 불안정한 환경을 고려하여 모바일 앱은 로컬 캐시에 촬영 데이터를 임시 저장 후 연결 복구 시 자동 업로드하는 구조를 채택한다.
2
AI 추론 서버 분리
YOLOv8 추론은 GPU 의존성이 높으므로 일반 API 서버와 별도 컨테이너로 분리하여 스케일 아웃과 버전 교체가 독립적으로 가능하도록 설계한다.
3
비동기 보고서 생성
PDF/DOCX 보고서 생성은 시간이 소요되므로 Celery 기반 비동기 작업 큐로 처리하고 완료 시 앱에 푸시 알림을 발송한다.
4
표준 양식 템플릿 매핑
국토안전관리원 점검 양식을 JSON 스키마로 정의하여, AI 탐지 결과와 필드 단위로 매핑되도록 설계한다. 양식 변경 시 스키마만 수정하면 코드 변경 없이 대응 가능하다.

시나리오별 데이터 흐름
컨테이너 구성 (Docker Compose)
A
app — FastAPI 메인 서버
REST API 처리, JWT 인증, DB 연결. 포트 8000. uvicorn 멀티 워커로 기동.
B
ai-worker — YOLOv8 추론 컨테이너
GPU 할당 컨테이너 (nvidia runtime). Celery worker로 기동하여 Redis 큐에서 추론 작업 수신. app 컨테이너와 네트워크 분리.
C
report-worker — 문서 생성 컨테이너
python-docx + ReportLab으로 PDF/DOCX 생성. CPU 전용. 완료 시 S3 업로드 및 FCM 푸시 발송.
D
db — PostgreSQL 15
볼륨 마운트로 데이터 영속화. 로컬 개발 시 docker-compose, 운영 시 AWS RDS로 교체.
E
redis — Redis 7
Celery 브로커 겸 결과 백엔드. 세션 캐시 및 API rate-limit 카운터도 담당.
