### 모델 학습 곡선 분석
- `Crack Detection(6.8)/runs/detect/train12/results.csv`(50 epoch) 기반으로 loss(box/cls/dfl, train vs val) + precision/recall/mAP 차트를 아티팩트로 제작.
- `train12`는 YOLOv8n(나노), 단일 클래스("Crack"), Roboflow `crack-wyt8q-akcdn` 데이터셋으로 train9→10→11→12 체크포인트를 이어 학습한 결과. mAP50 0.86, mAP50-95 0.54.

### 모델 개선 방향 논의
- YOLOv8 → 상위 버전(YOLO11 등) 교체는 전환 비용이 거의 없지만, 단일 클래스 + 소규모 데이터셋에서는 세대 업그레이드 효과가 제한적일 것으로 판단.
- 공개 사전학습 크랙 탐지 모델을 그대로 쓰는 것도 도메인(도로/콘크리트 vs 건물외벽)이 달라 검증 없이는 신뢰하기 어려움.
- 결론: 모델 교체보다 **데이터 쪽 개선(재라벨링 → 필요 시 데이터 보강)** 이 우선순위. 재라벨링 착수는 보류.

### 버그 수정
- `backend/app/services/grade.py`: `max_crack_mm < 0.1mm`인데 결함이 실제로 탐지된 경우 `calculate_grade`가 "A(이상없음)"을 반환하던 버그 수정 → docstring 의도대로 "B(주기적 모니터링)"로 정정.

### 발견했지만 아직 손 안 댄 이슈
- **균열 폭(mm) 계산이 고정 스케일**(`backend/app/services/detection.py`: `pixel_width * 0.1`)이라, 촬영 거리/기기에 따라 같은 균열도 다른 mm 값이 나오고 안전등급(A~E)이 흔들릴 수 있음. 기준 마커 또는 거리 보정 필요.
- **권한(authorization) 체크 부재** — `inspector_id`/`created_by`는 기록만 하고 조회·수정·삭제 어디서도 검사하지 않음. 로그인한 사용자가 다른 사용자의 프로젝트/사진/보고서를 ID만 알면 조작·삭제 가능 (IDOR).
- `Crack Detection(6.8)/init.py`에 Roboflow API 키가 평문으로 커밋되어 있음.
- 업로드 엔드포인트에 서버사이드 파일 크기 제한이 없음 (프론트엔드 20MB 제한은 클라이언트에서만 체크).

### 보류한 결정
- 백엔드(모델 포함)·프론트엔드 통합 패키징 + 폐쇄망(폐쇠환경) 배포 방식 — Docker 이미지 오프라인 번들(`docker save`/`load`) vs Electron+PyInstaller 데스크톱 앱 중 선택 필요. 비용 차이가 커서 추후 별도 논의.

### 자율주행 균열 스캔 모듈 추가 (`autonomous/`)
- Lamp AI 메카넘 자동차(시리얼/블루투스, `lamp-ai` 패키지) + NCAM 무선 카메라(USB 동글 수신, PC에선 일반 UVC 웹캠으로 인식)로 전진 주행하며 실시간 균열 탐지 → 탐지 시 정지+중앙 LED ON+사진 저장하는 독립 모듈. 백엔드/프론트엔드와 무관하게 동작, 모델 가중치(`crack_best.pt`)도 복제해서 완전히 독립 실행 가능.
- `drive_scan.py`: 키보드 조작(G 출발/SPACE 정지/ESC 종료) 버전. 제일 먼저 만들어서 실제 동작 확인함.
- `web_control.py`: 브라우저 조작 패널(FastAPI, 포트 8800). 캠 화면/전진·후진·좌·우·정지/속도/각도(서보)/탐지 on-off/연결 해제 UI.
  - `/`(설정 화면)에서 시리얼 포트·카메라를 스캔(새로고침 가능)해서 선택 → 연결 → `/control`로 이동하는 구조로 변경. 서버 자체는 하드웨어 연결 여부와 무관하게 항상 뜨고, 재연결도 서버 재시작 없이 웹에서 바로 가능.
  - "연결 해제" 버튼은 서버를 끄지 않고 모터만 정지시킨 뒤 설정 화면으로 돌아가도록 수정 (처음엔 서버 자체를 종료시키는 구조였음).

### 실기기 테스트 중 발견한 버그들 (전부 수정)
- **MJPEG 스트림 제너레이터가 종료 조건이 없어서**, `/exit` 호출해도 스트림이 열려있으면 uvicorn이 영원히 graceful shutdown을 못 끝내고 COM 포트를 계속 붙잡고 있었음 → 스트림 제너레이터에 `shutdown_event` 체크 추가.
- **OpenCV MSMF 백엔드가 NCAM 같은 무선 수신 동글에서 자주 grabFrame 실패** → `cv2.CAP_DSHOW` 백엔드로 전환.
- **일부 무선 카메라는 신호가 끊겨도 `read()`가 `ok=True`로 마지막 프레임을 계속 반환**해서 멈춘 걸 감지 못 함 → 동일 프레임이 일정 횟수 반복되면 정지로 간주하고 재연결하는 로직 추가.
- **DSHOW 백엔드는 같은 `VideoCapture` 객체에 `release()+open()`을 반복하면 "can't be used to capture by index" 상태로 완전히 망가짐** → 재연결 시 아예 새 `VideoCapture` 객체를 생성해서 교체하는 방식으로 변경.
- **치명적**: 재연결 로그의 한글 특수기호(`—`)가 일부 Windows 콘솔 인코딩(cp949)에서 `UnicodeEncodeError`를 던지며 백그라운드 스레드를 조용히 죽였음 — 영상이 멈추거나 아예 안 보이는 증상의 실제 원인. `sys.stdout/stderr.reconfigure(encoding='utf-8', errors='replace')`로 고정 + `vision_loop` 전체를 예외로부터 보호(어떤 에러가 나도 스레드 안 죽게).
