### 모델 학습 곡선 분석
- `Crack Detection(6.8)/runs/detect/train12/results.csv`(50 epoch) 기반으로 loss(box/cls/dfl, train vs val) + precision/recall/mAP 차트를 아티팩트로 제작.
- `train12`는 YOLOv8n(나노), 단일 클래스("Crack"), Roboflow `crack-wyt8q-akcdn` 데이터셋으로 train9→10→11→12 체크포인트를 이어 학습한 결과. mAP50 0.86, mAP50-95 0.54.

### 모델 개선 방향 논의
- YOLOv8 → 상위 버전(YOLO11 등) 교체는 전환 비용이 거의 없지만, 단일 클래스 + 소규모 데이터셋에서는 세대 업그레이드 효과가 제한적일 것으로 판단.
- 공개 사전학습 크랙 탐지 모델을 그대로 쓰는 것도 도메인(도로/콘크리트 vs 건물외벽)이 달라 검증 없이는 신뢰하기 어려움.
- 결론: 모델 교체보다 **데이터 쪽 개선(재라벨링 → 필요 시 데이터 보강)** 이 우선순위. 재라벨링 착수는 보류.

### 버그 수정
- `backend/app/services/grade.py`: `max_crack_mm < 0.1mm`인데 결함이 실제로 탐지된 경우 `calculate_grade`가 "A(이상없음)"을 반환하던 버그 수정 → docstring 의도대로 "B(주기적 모니터링)"로 정정.

### 발견했지만 아직 손 안 댄 이슈
- **균열 폭(mm) 계산이 고정 스케일**(`backend/app/services/detection.py`: `pixel_width * 0.1`)이라, 촬영 거리/기기에 따라 같은 균열도 다른 mm 값이 나오고 안전등급(A~E)이 흔들릴 수 있음. 기준 마커 또는 거리 보정 필요.
- **권한(authorization) 체크 부재** — `inspector_id`/`created_by`는 기록만 하고 조회·수정·삭제 어디서도 검사하지 않음. 로그인한 사용자가 다른 사용자의 프로젝트/사진/보고서를 ID만 알면 조작·삭제 가능 (IDOR).
- `Crack Detection(6.8)/init.py`에 Roboflow API 키가 평문으로 커밋되어 있음.
- 업로드 엔드포인트에 서버사이드 파일 크기 제한이 없음 (프론트엔드 20MB 제한은 클라이언트에서만 체크).

### 보류한 결정
- 백엔드(모델 포함)·프론트엔드 통합 패키징 + 폐쇄망(폐쇠환경) 배포 방식 — Docker 이미지 오프라인 번들(`docker save`/`load`) vs Electron+PyInstaller 데스크톱 앱 중 선택 필요. 비용 차이가 커서 추후 별도 논의.
